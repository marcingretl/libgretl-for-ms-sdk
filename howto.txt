Environment:
1. Microsoft Visual Studio (2022 used).
3. MSYS2 with working gendef.exe (UCRT64 used).

Steps:
1.a.
Generate libgretl-1.0-1.def by running: "gendef.exe libgretl-1.0-1.dll". Resulting file should look like this:
;
; Definition file of libgretl-1.0-1.dll
; Automatic generated by gendef 1.1
; written by Kai Tietz 2008
; The def file has to be processed by --kill-at (-k) option of dlltool or ld
;
LIBRARY "libgretl-1.0-1.dll"
EXPORTS
BFGS_defaults
BFGS_max
BFN_panel_DW_pvalue
...
...
...
Note: libgretl-1.0-1.def might be generated automatically during compilation (via "-Wl,--output-def=libgretl-1.0-1.def").

1.b.
Generate libm.dll doing the following in MSYS2 (ucrt64 used):
ar -x libm.a
CC -shared lib64_libm_a-libm_dummy.o -o libm.dll (clang used)


2.a.
Run "lib.exe /machine:x64 /def:libgretl-1.0-1.def /out:gretl-1.0.lib".
Note: It should/must be called from within 'x64 Native Tools Command Prompt for VS'. As a result we should get two binary files, i.e. gretl-1.0.exp and gretl-1.0.lib.
As an alternative command, one may use: "dlltool.exe -d libgretl-1.0-1.def -l gretl-1.0.lib"
Now libgretl-1.0-1.dll is ready to be used by native MS Windows compilers.

2.b.
The same procedure apply to: libm.dll, libxml2-2.dll (as xml2.lib), libfftw3-3.dll (as fftw3.lib)

2.c.
Generate intl.lib and glib-2.0.lib using intl.dll and libglib-2.0-0.dll from an official gretl distribution.
